# DF2-Missions-Navigator

DF2-Missions-Navigator - это инструмент для работы с миссиями игры Death Frontier 2. Он собирает информацию о миссиях из разных источников, обрабатывает её и помогает оптимально планировать выполнение миссий.

## Основные возможности

- Парсинг данных о миссиях с сайтов `df2haven.com` и `df2profiler.com`
- Получение данных о карте игры
- Фильтрация миссий по типу, району и уровню
- Построение оптимального маршрута для выполнения миссий
- Кеширование данных для ускорения работы
- Подробное логирование

## Архитектура проекта

- **Парсеры** - отвечают за получение данных из внешних источников
- **Репозитории** - работа с данными, их фильтрация и обработка
- **Сервисы** - бизнес-логика приложения
- **Фабрики** - создание компонентов с необходимыми зависимостями
- **Модели** - структуры данных и перечисления
- **Утилиты** - вспомогательные инструменты (логирование, кеширование, сеть)

## Система логирования

В проекте реализована гибкая система логирования:

- Логи сохраняются в директории `logs/app.log`
- Настроена ротация логов (максимальный размер 5MB, хранение до 7 файлов)
- Одновременный вывод логов в консоль и файл
- Различные уровни детализации (INFO, DEBUG, ERROR)
- Логирование по классам и функциям

Для получения логгера в коде используются функции:
```python
# Простой логгер с указанием имени
logger = get_logger("component_name")

# Логгер для класса (автоматически определяет имя класса)
logger = get_class_logger(self)

# Логгер для функции (автоматически определяет имя функции)
logger = get_function_logger(func)
```

## Система кеширования

Реализовано двухуровневое кеширование данных:

1. **Кеш в памяти** - быстрый доступ к часто используемым данным
   ```python
   @cache_to_memory(ttl=600, namespace="missions_routes")
   def my_function():
       ...
   ```

2. **Файловый кеш** - сохранение данных между запусками программы
   ```python
   @cache_to_file(ttl=7200, namespace="df2profiler_missions", use_pickle=True)
   async def get_missions_list():
       ...
   ```

Для обоих типов кеша реализована поддержка:
- TTL (Time To Live) - время жизни кеша
- Пространств имен - для разделения кеша между разными компонентами
- Работы с синхронными и асинхронными функциями
- Сохранение типов данных (включая Pydantic модели и Enum)

### Специальная обработка типов объектов

Система кеширования поддерживает сохранение и восстановление следующих типов данных:
- **Pydantic модели** - сохраняются со своей структурой и восстанавливаются как полноценные объекты
- **Enum значения** - сохраняются с информацией о типе и восстанавливаются как правильный экземпляр Enum
- **Наборы (set)** - сохраняются с типом и восстанавливаются как множества
- **Кортежи (tuple)** - сохраняются с типом и восстанавливаются как кортежи
- **Вложенные структуры данных** - корректно обрабатываются любой вложенности

Для этого реализован:
- **Кастомный JSON энкодер** - добавляет мета-информацию о типе объекта в JSON
- **Кастомный JSON декодер** - восстанавливает оригинальные типы объектов из JSON
- **Pickle сериализация** - для сложных объектов рекомендуется использовать параметр `use_pickle=True`

Управление кешем доступно через командную строку:
```bash
# Вывести информацию о кеше
python run.py --cache-info

# Очистить кеш перед запуском
python run.py --clear-cache
```

## Примеры использования

```python
# Создание сервиса
missions_service = create_missions_service()

# Получение всех миссий
missions = await missions_service.get_all_missions()

# Получение автостартовых миссий в определенном районе
autostart_missions = await missions_service.get_autostart_missions(
    districts=[District.RAVENWALL_HEIGHTS]
)

# Построение оптимального маршрута
route = await missions_service.get_missions_route(
    missions=autostart_missions,
    start_building=start_point
)
```
